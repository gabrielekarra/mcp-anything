# Examples

MCP servers auto-generated by mcp-anything from real-world API specs — no manual editing.

## GitHub API → MCP Server

**Source:** [GitHub REST API](https://docs.github.com/en/rest) via its [OpenAPI 3.0 spec](https://github.com/github/rest-api-description) (1,093 endpoints)

**Command:**
```bash
mcp-anything generate https://raw.githubusercontent.com/github/rest-api-description/main/descriptions/api.github.com/api.github.com.json --name github --no-llm
```

**What was generated:** A complete MCP server with **1,093 tools** — one for every GitHub REST API endpoint — in seconds.

These examples were made by the `generate` codebase scanner with `--no-llm`: one tool per endpoint, with the spec's own names and descriptions. They show what the scanner extracts, not the tool design `build` does with a brief (which groups related operations into fewer tools).

### Sample generated tools

| Tool name | HTTP method | Endpoint | Description |
|-----------|-------------|----------|-------------|
| `repos_list_for_authenticated_user` | GET | `/user/repos` | List repositories for the authenticated user |
| `issues_create` | POST | `/repos/{owner}/{repo}/issues` | Create an issue |
| `pulls_create` | POST | `/repos/{owner}/{repo}/pulls` | Create a pull request |
| `search_repos` | GET | `/search/repositories` | Search repositories |
| `gists_create` | POST | `/gists` | Create a gist |
| `actions_list_workflow_runs` | GET | `/repos/{owner}/{repo}/actions/runs` | List workflow runs |
| `repos_create_or_update_file_contents` | PUT | `/repos/{owner}/{repo}/contents/{path}` | Create or update file contents |
| `activity_list_repos_starred_by_user` | GET | `/users/{username}/starred` | List repos starred by a user |

### Setup

```bash
cd examples/github-server
pip install -e .

# Set your GitHub PAT and base URL
export GITHUB_BASE_URL=https://api.github.com
export GITHUB_API_KEY=ghp_your_token_here

# Run the server
mcp-github
```

Or add to your MCP client config:
```json
{
  "mcpServers": {
    "github": {
      "command": "mcp-github",
      "args": [],
      "env": {
        "GITHUB_BASE_URL": "https://api.github.com",
        "GITHUB_API_KEY": "ghp_your_token_here"
      }
    }
  }
}
```

### Trade-offs

A server with a tool for every endpoint is complete, but 1,093 tools is far more than an agent can choose from well, and the list alone fills a large part of a model's context. `mcp-anything grade` reports exactly that (rules G01 and G02). For agents, scope it (next example) or use `build` with a brief, which designs fewer, grouped tools.

## GitHub API → Scoped MCP Server (matching official tools)

**Source:** Same [GitHub REST API OpenAPI spec](https://github.com/github/rest-api-description) as above, but scoped with a `scope.yaml` file to match only the tools the [official GitHub MCP server](https://github.com/github/github-mcp-server) exposes.

**Command:**
```bash
mcp-anything generate \
  https://raw.githubusercontent.com/github/rest-api-description/main/descriptions/api.github.com/api.github.com.json \
  --name github-scoped --no-llm \
  --scope-file examples/github-server-scoped/scope.yaml \
  -o examples/github-server-scoped
```

**Result:** 1,093 auto-detected capabilities → **67 tools** after scope filtering (1,032 excluded).

### Why 67 and not 80?

When this example was made (March 2026), the official server listed **80 tools**, but:
- **11 use GraphQL or Copilot-specific APIs** that don't appear in the REST OpenAPI spec (discussions, projects, Copilot assignment)
- **2 official tools map to the same REST endpoint** (`push_files` and `create_or_update_file` both use `PUT /repos/{owner}/{repo}/contents/{path}`; `search_issues` and `search_pull_requests` share the same search endpoint)

That leaves **67 unique REST tools** — exactly what we generate.

Compare any two servers yourself with `mcp-anything grade`, for example the official GitHub server against this one: the grade says how easy each tool list is for an agent to use, with the same rules for both.

### How the scope file works

The scope file uses two mechanisms:
1. `exclude_patterns: ["*"]` — excludes everything by default
2. `enabled: true` on each tool we want — overrides the pattern for that specific tool

```yaml
# Exclude everything by default
exclude_patterns: ["*"]

capabilities:
  # Only these tools are generated:
  - name: repos_get_content             # official: get_file_contents
    enabled: true
  - name: issues_create                 # official: create_issue
    enabled: true
  - name: pulls_list                    # official: list_pull_requests
    enabled: true
  # ... 64 more tools
```

### Reproduce it

```bash
# Step 1: Install mcp-anything
pip install mcp-anything

# Step 2: Generate the scoped server
mcp-anything generate \
  https://raw.githubusercontent.com/github/rest-api-description/main/descriptions/api.github.com/api.github.com.json \
  --name github-scoped --no-llm \
  --scope-file examples/github-server-scoped/scope.yaml

# Step 3: Install and run
cd mcp-github-scoped-server
pip install -e .
export GITHUB_SCOPED_BASE_URL=https://api.github.com
export GITHUB_SCOPED_API_KEY=ghp_your_token_here
mcp-github-scoped
```

Or use **review mode** to curate your own subset interactively:
```bash
# Analyze and pause — writes scope.yaml with all 1,093 capabilities
mcp-anything generate \
  https://raw.githubusercontent.com/github/rest-api-description/main/descriptions/api.github.com/api.github.com.json \
  --name github-custom --no-llm --review

# Edit the scope file (set enabled: false on what you don't want)
vim mcp-github-custom-server/scope.yaml

# Resume — generates only the tools you kept
mcp-anything generate \
  https://raw.githubusercontent.com/github/rest-api-description/main/descriptions/api.github.com/api.github.com.json \
  --name github-custom --resume
```
