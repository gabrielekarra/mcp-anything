## Generate an MCP server with mcp-anything

mcp-anything (https://github.com/gabrielekarra/mcp-anything) turns a codebase, an API spec, or a
plain-language brief into a working MCP server: Python/FastMCP by default, or TypeScript/mcp-use
with `--target mcp-use`.

### 1. Make sure the CLI is 0.3.0 or later

!`command -v mcp-anything >/dev/null 2>&1 && mcp-anything --version || echo "not installed"`

If it is missing or older than 0.3.0, install or upgrade it. Servers generated by 0.2.x do not start
with `mcp` 2.x.

```bash
pip install -U "mcp-anything[llm]"
```

### 2. Find out what to expose

Ask only what's missing:
- **The source**: a local codebase path, or an OpenAPI/GraphQL/gRPC spec (file path or URL).
- **What agents should be able to do with it**: a sentence or two of use cases is enough for the
  curated path below.

### 3. Pick a model

The LLM steps use `--model provider:model`, or `MCP_ANYTHING_MODEL` when the flag is not given.
The default is `anthropic:claude-opus-5-5`. Pick one the user has credentials for:

- `anthropic:<model>` needs `ANTHROPIC_API_KEY`
- `openai:<model>` needs `OPENAI_API_KEY`, and `openrouter:<model>` needs `OPENROUTER_API_KEY`
- `ollama:<model>`, `lmstudio:<model>`, `llamacpp:<model>` and `vllm:<model>` run locally
  (`MCP_ANYTHING_BASE_URL` overrides the address)

With no usable model, pass `--no-llm`. Every step then falls back to a deterministic design. It
works, but grouping and descriptions are better with a model.

### 4. Generate

- **One command** (no use cases given):
  `mcp-anything <path-or-url> -o <output-dir> --install claude-code`
  This drafts a brief from the source, builds the server, and saves the brief as
  `<output-dir>/brief.yaml`, so the user can edit it and rebuild.
- **Curated, agent-optimized tools** (use cases given): write a short brief to a temp YAML file
  (`server_name`, `domain_description`, `use_cases: [...]`), then run:
  `mcp-anything build --brief <brief.yaml> --data-source <path-or-spec> -o <output-dir> --install claude-code`
- Add `--target mcp-use` to either command for TypeScript instead of Python.
- `--install` accepts `claude-code`, `claude-desktop`, `cursor` and `vscode`, and can be repeated.
  Leave it out if the user does not want their client config changed. You can add the server
  later with `mcp-anything install <output-dir> --client <client>`, or use `--print` to show
  the config entry without writing it.

### 5. Check the result

`grade` and `eval` start the server, so its dependencies must be installed. `--install` already did
that. Otherwise run `pip install -e <output-dir>` (Python) or `npm install` in `<output-dir>`
(TypeScript) first.

- `mcp-anything grade <output-dir>` scores how easy the tools are for an agent to pick and call,
  on 15 rules, and lists what to fix. A generated server should grade A (90 or more). If it scores
  lower, report the top findings.
- `mcp-anything validate <output-dir>` checks the server against mcp-anything's output contract
  (tool shape, transport, telemetry, packaging).
- `mcp-anything eval <output-dir>` runs the generated `eval_cases.json` against the live server.
  Add `--agent` to have a model solve each use case with the server's tools. This needs a working
  backend behind the server.

### 6. Report back

Report the output directory, the tool count, the grade, and which clients the server was added to.
If it was not installed, show the config entry from
`mcp-anything install <output-dir> --client <client> --print`. The user should
restart the client, or run `/mcp` in Claude Code, to see the new tools.
